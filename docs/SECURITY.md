# Secrets

## Where secrets live now

The code has no secrets. Every one is read from an environment variable:
- locally from `.env`, which git ignores; `.env.example` shows the names with empty values
- on Render from the service's environment (`JWT_SECRET` is generated by Render)
- in tests from dummy values in `application-test.properties`

## Scanning

Every push and pull request runs [gitleaks](https://github.com/gitleaks/gitleaks) v8.30.1 over **all commits**: the `Secret scan` job in `.github/workflows/ci.yml`. A new secret fails the build.

- `.gitleaks.toml` adds two rules to the default set. The default rules missed two kinds of secret that were committed here:
  - a secret hard-coded in a Java string constant (test files excluded)
  - a literal Spring `*.password`, or a non-empty `${VAR:default}` fallback
- The rules were checked against a throwaway repository with three planted secrets (a Java constant, a Spring password, a `.env` key). All three were reported, and an empty `${MAIL_PASSWORD:}` was not.
- `.gitleaksignore` lists the findings in old commits (below). They can't be removed from history without rewriting it, so the scan skips them. **They are only harmless once rotated.**

To run the scan locally:
```bash
docker run --rm -v "$PWD:/repo" zricethezav/gitleaks:v8.30.1 git /repo --config /repo/.gitleaks.toml \
  --gitleaks-ignore-path /repo/.gitleaksignore --redact --no-banner --log-opts="--all"
```

The `ecommerce-server` repository is **private** (19 Nov 2026), so these values have not been public. Before making it public, either:
- rotate everything above (then the old values in history are useless), or
- rewrite the history to remove them (`git filter-repo --replace-text`). Rewriting changes every commit id from the first commit on, so the ids quoted in these docs would need updating, and every clone would need re-cloning.

The frontend repository is public. Its full-history scan found nothing.
